# C4 基线、冻结原型与 D4 迁移诊断 V1

所有编码器保持冻结。本轮补齐光谱/PCA64 的欧氏 1-NN，并用原样的类内支持集构建四种原型分类器；这些是冻结编码器上的统计分类头，不是新训练的 Prototypical Networks。

**D4 迁移已按输入兼容性规则停止。** D4 仅覆盖 599.78354–3995.98555，锁定输入为 399.1927–4000.6045，104 个低端及 3 个高端坐标未测量；没有外推、补零、改网格或重新训练。物理信号和实物身份也未确认。`d4_transfer_metrics.csv` 只有明确 blocked 状态，空分数不是零准确率。完整依据见 `d4_dataset_audit.md`。

## 评估条件

三任务、三种子、1/5/10/20-shot，每个 shot 200 个原配对 episode。基类每类固定 20 条，新类按原顺序逐个加入 K 条，旧样本保留。全部 support/query 和基类 exemplar 直接读取 `frozen_incremental_v1/sessions.json`。PCA64 和类内协方差只拟合原 base_train，在新类到达后不重拟合。SVM 参数沿用父实验，原型 reg=0.001、tau=5，距离和参数均不使用新类 query 选择。

基类 query 仍是参与 checkpoint/C 选择的 base_validation，C4 新类也已被查看，实物分组未验证。所以总体与基类指标为探索性验证集复用结果。M1 编码器曾用全部基类训练标签，PCA/协方差有基类统计拟合阶段，光谱参考没有编码器训练；分类头支持预算一致不等于所有历史学习机会一致。

原型只计算并保存到达类的均值/度量，旧类状态不改；共享 Mahalanobis 的逆矩阵预先计算，收缩 Mahalanobis 对到达类单独计算完整精度矩阵。P0/P1 只留均值向量；P2 另有一份共享 128×128 矩阵，P3 另有每类 128×128 精度矩阵和全局先验，不能只数原型向量来宣称省内存。

特征库、类度量、全局度量、PCA/CNN 变换参数分开记录；统计不含 Python 对象、标签元数据及分配器开销，不是进程 RAM 实测。所有 M1 头的共同编码器参数成本相同。PCA 映射也占存储，已列入变换参数。

注册时间包括新 support 的冻结编码/投影与头更新，排除共享预处理；SVM 整理全库后完整重拟合，1-NN 采用已有 sklearn 库整理与索引准备。原型不重拟合全局分类器。预测在缓存 query 特征上计时，不是包含 query 编码的端到端延迟。NumPy/sklearn 数值线程限制为 1，TensorFlow 为 4；这里重新计时的参考结果与父运行逐 episode 数值核对，不能把父运行的不同线程耗时直接拼入比较。PCA、先验和原型基类初始化另存 `preparation_costs.json`，未隐入新类成本。

## 研究问题与下一步

1. M1 是否超过光谱 1-NN、PCA64 1-NN：看配对表中 M1_1nn 对应两行的总分及新类差值；两者都必须保留为强基线，不能只与弱 M0 比。
2. 原型能否接近 M1 1-NN：看四个原型相对 M1_1nn 的配对差值，并同时检查新类表现，不能用基类高分遮住新类低分。
3. 存储和注册是否改善：均值原型的特征库明显更小；共享/收缩度量的矩阵可能抵消节省，具体字节和实测计时在上表，不能预设所有原型都更省。
4. M1 能否迁移 D4：本轮无法回答，输入不兼容导致实验未执行，不能将 blocked 记为模型迁移失败或成功。
5. 是否必须换新 prototype-learning objective：本轮不能证明“必要”。如果现有固定度量已接近邻近方法，优先验证这种无训练头；若原型明显落后，应先区分均值几何、类别内多模态、范数与度量问题，再设计仅用基类开发数据的后续对照，不根据当前新类 query 继续调参。
6. 下一阶段首先补充覆盖锁定网格、信号语义可核实且实物身份可审计的外部数据。在独立验证前，不宣称跨数据库确认性泛化，也不依据这一轮直接训练新 ProtoNet/SupCon。
